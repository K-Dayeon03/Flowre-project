# 직원 승인 · 매장 주소 등록 — 테스트 가이드

본사 매장 등록 시 **주소(우편번호·도로명) 조회**와, 직원 등록 시 **점장 승인** 플로우를 로컬에서 끝까지 검증하는 절차입니다.

---

## 0. 사전 준비

### 인프라
- MySQL 8 (`localhost:3306`, db `flowre`, `root` / `1234`)
- Redis (`localhost:6379`)

### 백엔드 기동
```bash
cd server
./gradlew bootRun --args='--flowre.inventory.auto-load=false --spring.jpa.show-sql=false'
```
> `auto-load`/`show-sql`을 끄지 않으면 부팅 시 재고 샘플 적재로 SQL 로그가 폭주해 기동이 느려집니다.

### 프론트엔드 기동
```bash
cd client
npm install        # react-native-webview 포함 의존성 설치 (최초 1회)
npm run start      # Expo 개발 서버
```
> 주소 검색은 `react-native-webview`(다음 우편번호 서비스)를 사용합니다. Expo Go에는 기본 번들되어 있고, 커스텀 dev build를 쓴다면 `npx expo install react-native-webview`로 네이티브 링크를 맞추세요.

## 1. 최초 로그인 (부트스트랩 본사 ADMIN)

테스트용 하드코딩 계정은 제거되었고, `AdminAccountInitializer`가 설정값 기반으로 ADMIN 계정 1개를 멱등 생성합니다.

| 항목 | 값 |
|------|----|
| 점별 코드 | `0000` |
| 직원 아이디 | `0000ADMN!` |
| 비밀번호 | `flowre-admin-1234!` |
| 권한 | `ADMIN` |

- `status` 기본값이 `ACTIVE`라 로그인 차단에 걸리지 않습니다.
- 환경변수로 오버라이드 가능: `FLOWRE_ADMIN_PASSWORD`, `FLOWRE_ADMIN_EMPLOYEE_CODE` 등 / 비활성화: `FLOWRE_ADMIN_ENABLED=false`
- ADMIN 또는 본사 직원(`HQ_STAFF`)만 매장·직원을 등록할 수 있습니다.

## 2. 기능 ① — 매장 등록 (주소 조회)

**홈 → "매장 등록"** (ADMIN/HQ_STAFF에게만 노출)

1. 점별 코드(숫자 4자리)·매장명 입력
2. **"주소 검색"** 버튼 → 다음 우편번호 WebView 모달이 열림
3. 검색 후 주소 선택 → `(우편번호) 도로명 주소`가 자동 입력됨 (별도 API 키 불필요)
4. **상세 주소**(동·층·호 등) 직접 입력 (선택)
5. **"등록"** → 목록에 매장이 주소와 함께 추가됨

### 검증 포인트
- 주소를 선택하지 않고 등록하면 `"주소 검색으로 매장 주소를 선택해주세요."` 안내
- 저장되는 필드: `postalCode`(필수, 5자리) · `roadAddress`(필수) · `jibunAddress`(선택) · `detailAddress`(선택)
- dev 환경에서 시드된 `1001 강남점`은 주소가 비어 있으므로, 주소 흐름은 **새 매장 등록**으로 확인하는 것이 명확합니다.

### 기존 매장 주소 수정 (API)
```
PATCH /api/stores/{storeId}/address
{ "postalCode": "06035", "roadAddress": "서울 강남구 가로수길 5", "detailAddress": "2층" }
```

## 3. 기능 ② — 직원 등록 & 점장 승인

### 승인 규칙
| 등록 대상 | 해당 매장에 활성 점장 존재 | 결과 |
|-----------|:--:|:--|
| 일반 직원(`STORE_STAFF`) | ✅ 있음 | `PENDING` 생성 + 점장에게 승인 알림 (승인 전 로그인 불가) |
| 일반 직원(`STORE_STAFF`) | ❌ 없음 | **등록 거부** (`STORE_MANAGER_REQUIRED`) — 점장을 먼저 등록해야 함 |
| 점장(`STORE_MANAGER`) | ❌ 없음 (첫 점장) | `ACTIVE` (부트스트랩, 즉시 로그인 가능) |
| 점장(`STORE_MANAGER`) | ✅ 있음 | `PENDING` (기존 점장이 승인) |
| 본사 직원(`HQ_STAFF`) | — | `ACTIVE` (즉시 로그인 가능) |

> 핵심 흐름: **점장을 먼저 등록**해야 그 매장의 직원을 등록할 수 있다. 본사가 발급한 직원이 **실제 그 매장 소속인지**를 점장이 확인·승인하며, 직원 등록 시 그 점장에게 승인 요청 알림이 간다.

### 직원 아이디 형식
- `숫자 4자리(점별 코드) + 영문 4글자 + 특수문자 1개` — 예: `1001WXYZ!`
- 점별 코드로 시작해야 하며, 해당 매장이 활성 등록되어 있어야 함

### 전체 시나리오

**① 점장 발급 (즉시 활성)**
1. ADMIN으로 **홈 → "직원 등록"**
2. 매장 `1001`에 권한 **점장**, 직원 아이디 예 `1001MGRA!` 발급
3. 그 매장에 아직 활성 점장이 없으므로 → **ACTIVE** (목록에 "활성" 뱃지)
4. 이 점장 계정으로 로그인 가능: 점별 코드 `1001` / 아이디 `1001MGRA!` / 발급한 비밀번호

**② 직원 발급 (승인 대기)**
1. ADMIN으로 같은 매장 `1001`에 권한 **직원**, 예 `1001WXYZ!` 발급
2. 이제 매장에 활성 점장이 있으므로 → **PENDING** (목록에 "승인 대기" 뱃지)
3. 이 직원으로 로그인 시도 → `점장 승인 대기 중인 계정입니다. 승인 후 로그인할 수 있습니다.` 로 차단

**③ 점장 승인**
1. ①의 점장 계정으로 로그인
2. **홈 → "직원 승인"** (점장/관리자에게만 노출)
3. 승인 대기 목록에서 해당 직원의 **"승인"** 클릭 → 확인
4. (또는 **"거절"** → 사유 입력 → `REJECTED`, 거절 사유는 로그인 시 안내)

**④ 승인 후 로그인**
- 승인된 직원으로 다시 로그인 → 정상 진입

### 검증 포인트
- PENDING/REJECTED 계정은 비밀번호가 맞아도 로그인 불가 (`ACCOUNT_PENDING_APPROVAL` / `ACCOUNT_REJECTED`)
- 점장은 **자기 매장** 직원만, ADMIN은 **브랜드 전체** 직원을 승인 가능 (타 매장 승인 시 `APPROVAL_NOT_ALLOWED`)
- 이미 활성/거절된 직원을 다시 승인하려 하면 `EMPLOYEE_NOT_PENDING`
- 본사 직원(HQ_STAFF)은 "직원 승인" 화면 접근 불가
- 승인 대기 직원 생성 시, 해당 매장 활성 점장에게 FCM 푸시 발송 (현재 `ApprovalNotificationService`는 발송 지점 **로깅 스텁** — 실제 발송은 `firebase-admin` 연동 시 활성화)

## 4. API 요약

| 메서드 | 경로 | 권한 | 설명 |
|--------|------|------|------|
| POST | `/api/auth/login` | 전체 | 로그인 (PENDING/REJECTED 차단) |
| POST | `/api/stores` | ADMIN/HQ_STAFF | 매장 등록 (주소 포함) |
| PATCH | `/api/stores/{id}/address` | ADMIN/HQ_STAFF | 매장 주소 수정 |
| GET | `/api/stores` | ADMIN/HQ_STAFF | 매장 목록 |
| POST | `/api/employees` | ADMIN/HQ_STAFF | 직원 발급 (승인 필요 시 PENDING) |
| GET | `/api/employees` | ADMIN/HQ_STAFF | 직원 목록 (status 포함) |
| GET | `/api/employees/pending` | STORE_MANAGER/ADMIN | 승인 대기 목록 |
| POST | `/api/employees/{id}/approve` | STORE_MANAGER/ADMIN | 직원 승인 |
| POST | `/api/employees/{id}/reject` | STORE_MANAGER/ADMIN | 직원 거절 (사유 필수) |

### 관련 에러 코드
| 코드 | 의미 |
|------|------|
| `USER_005` `ACCOUNT_PENDING_APPROVAL` | 점장 승인 대기 중 (로그인 차단) |
| `USER_006` `ACCOUNT_REJECTED` | 승인 거절됨 (로그인 차단) |
| `USER_007` `APPROVAL_NOT_ALLOWED` | 승인 권한 없음 (타 매장 등) |
| `USER_008` `EMPLOYEE_NOT_PENDING` | 승인 대기 상태가 아님 |
| `USER_009` `STORE_MANAGER_REQUIRED` | 직원 등록 전 해당 매장에 점장이 먼저 등록되어야 함 |

## 5. 트러블슈팅

- **로그인이 계속 막힘**: 발급한 직원이 PENDING일 수 있음 → 점장 승인 진행 또는 본사 직원/첫 점장으로 테스트
- **스테일 유저로 충돌**: `DELETE FROM users;` 후 백엔드 재기동 → ADMIN 멱등 재생성
- **`status` 컬럼 추가 실패**: `users.status`는 DB 기본값 `'ACTIVE'`(`columnDefinition`)로 정의되어 기존 행이 있어도 `ddl-auto=update`로 안전하게 추가됨. 그래도 문제가 나면 테이블 재생성
- **주소 검색 모달이 빈 화면**: 인터넷 연결 필요(다음 우편번호 스크립트 로드). 커스텀 dev build면 webview 네이티브 링크 확인
```
