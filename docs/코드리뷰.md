# Flowre 서버 코드 리뷰

> **역할 분담**
> - **리뷰 작성**: claude.ai(Cowork)에서 코드를 학습하며 발견한 문제를 이 파일에 누적 기록한다.
> - **수정 작업**: Claude Code가 이 파일을 읽고 `미해결` 항목을 수정한 뒤 `상태`를 갱신한다.
>
> 이 파일이 코드 리뷰의 **유일한 원본**이다. 다른 곳에 사본을 만들지 않는다.

---

## Claude Code 작업 방법

1. 사용자가 수정할 번호를 지정하면(예: "코드리뷰 #1 고쳐줘") 그 항목만 수정한다. 번호 지정이 없으면 🔴 → 🟠 → 🟡 순서로 `미해결` 항목 **하나**만 제안하고 확인을 받는다.
2. 수정 전에 `위치`의 코드를 직접 열어서 리뷰 내용이 지금도 유효한지 확인한다. 이미 고쳐졌거나 내용이 틀렸다면 수정하지 않고 `비고`에 적는다.
3. `CLAUDE.md`의 Code Style Rules를 지킨다. 특히 JavaDoc 주석과 JUnit5 테스트를 함께 작성한다.
4. 서버 테스트를 실행해서 통과를 확인한다: `cd server && ./gradlew test`
5. 이 파일의 해당 행을 갱신한다.
   - `상태`: `해결 (YYYY-MM-DD)`
   - 아래 **수정 이력** 표에 한 줄 추가 (번호, 날짜, 변경 파일, 요약, 테스트)
6. `상태`가 `확인 필요`나 `보류`인 항목은 사용자 확인 없이 수정하지 않는다.
7. 커밋은 사용자가 요청할 때만 한다. 커밋 메시지는 한글로 작성한다. (예: `fix: 코드리뷰 #1 JWT 비밀키 기본값 제거`)

## 작성 규칙

| 항목 | 값 |
|---|---|
| 심각도 | 🔴 높음 (보안·데이터 손상) / 🟠 중간 (버그 가능성·운영 위험) / 🟡 낮음 (품질·가독성) / ⚪ 참고 (확인 필요·문서) |
| 분류 | 보안 / 버그 / 설계 / 설정 / 품질 / 문서 |
| 상태 | 미해결 / 확인 필요 / 해결 (날짜) / 보류 (사유) |
| 번호 | 삭제하지 않고 이어서 부여한다 (#18, #19 …) |
| 경로 약어 | `resources/` = `server/src/main/resources/` · `config/`, `exception/`, `util/`, `response/` = `server/src/main/java/com/flowre/server/global/…` · `domain/` = `server/src/main/java/com/flowre/server/domain/` |
