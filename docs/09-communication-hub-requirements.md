# 본사-매장 커뮤니케이션 허브 요구사항

> 목적: 이미 구현된 공지, 문서, 채팅, 문의/AS를 사용자가 한 곳에서 확인하고 처리할 수 있게 정리한다.

---

## 1. 현재 상태

이미 다음 기능은 기반이 있다.

| 기능 | 현재 상태 |
|------|-----------|
| 공지 | 목록, 상세, 작성, 읽음 수 기반 있음 |
| 문서 | 업로드, 목록, 상세 기반 있음 |
| 채팅 | 그룹/1:1 채팅 기반 있음 |
| 문의/AS | 접수, 상태 변경, 대시보드 요약 기반 있음 |
| 알림 | 인앱 알림 도메인 기반 있음 |

다만 사용자가 “본사에서 온 일”을 한 화면에서 처리하는 허브 구조는 아직 약하다.

---

## 2. 허브에서 묶을 항목

| 항목 | 설명 |
|------|------|
| 본사 공지 | 전체 또는 매장 대상 공지 |
| 매장별 맞춤 알림 | 특정 매장에만 필요한 알림 |
| 업무 지시 | 스케줄 또는 본사 요청 업무 |
| 문의/AS 처리 상태 | 대기/진행/완료 상태 |
| 문서/매뉴얼 검색 | 업무 중 필요한 문서 빠른 검색 |
| 채팅 미확인 | 안읽은 채팅방과 메시지 |

---

## 3. 사용자 흐름

### 3.1 매장 직원/점장

1. 홈에서 미확인 공지, 업무 지시, 문의/AS 상태를 확인한다.
2. 필요한 항목을 눌러 상세 화면으로 이동한다.
3. 문서/매뉴얼을 검색한다.
4. 문의/AS 답변 또는 채팅 메시지를 확인한다.

### 3.2 본사 직원

1. 매장별 미처리 업무와 문의/AS 상태를 확인한다.
2. 특정 매장에 맞춤 알림 또는 업무 지시를 보낸다.
3. 문서/매뉴얼을 등록하고 공유한다.
4. 공지 읽음 여부와 미처리 상태를 추적한다.

---

## 4. 서버 요구사항

### 4.1 HubSummary 응답

| 필드 | 설명 |
|------|------|
| unreadNoticeCount | 미확인 공지 수 |
| unreadChatCount | 미확인 채팅 수 |
| pendingScheduleCount | 미완료 업무 수 |
| pendingInquiryCount | 미처리 문의 수 |
| pendingAsCount | 미처리 AS 수 |
| recentNotifications | 최근 알림 목록 |
| recentDocuments | 최근 문서 목록 |

### 4.2 API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/hub/summary` | 커뮤니케이션 허브 요약 |
| GET | `/api/hub/search` | 공지/문서/매뉴얼 통합 검색 |
| POST | `/api/notifications/store-targeted` | 매장 대상 맞춤 알림 생성 |

### 4.3 권한

- STORE_STAFF는 본인 매장 대상 항목만 본다.
- STORE_MANAGER는 본인 매장 대상 항목과 직원 응답 현황을 본다.
- HQ_STAFF는 브랜드 내 전체 매장을 본다.

---

## 5. 앱 요구사항

### 5.1 허브 화면

- 미확인 공지
- 안읽은 채팅
- 미완료 업무 지시
- 문의/AS 처리 상태
- 최근 문서
- 문서/매뉴얼 검색

### 5.2 홈 대시보드 연결

- 홈에서 허브 요약을 먼저 보여준다.
- 중요한 항목은 상단에 표시한다.
- `바로가기`를 통해 공지, 문서, 채팅, 문의/AS로 이동한다.

---

## 6. 완료 기준

- 사용자가 홈에서 본사-매장 커뮤니케이션 상태를 한 번에 볼 수 있다.
- 공지/문서/매뉴얼 통합 검색이 가능하다.
- 매장별 맞춤 알림을 본사에서 보낼 수 있다.
- 미처리 문의/AS 상태가 허브와 상세 화면에서 일관되게 보인다.
- 알림/공지/채팅/문서 접근 권한이 역할별로 지켜진다.
