# P0 기능 로드맵 — Flowre

> 현재 구현 상태를 기준으로, 다음 단계에서 바로 개발할 기능을 정리한다.
> 상세 요구사항은 기능별 문서로 분리한다.

---

## 1. 우선순위 요약

| 우선순위 | 기능 | 현재 상태 | 다음 목표 |
|----------|------|-----------|-----------|
| P0-1 | 재고 부족/소진 알림 | 부분 구현 | `minQuantity` 기준 알림, 상단 정렬, 뱃지, 알림 생성 |
| P0-2 | 모바일 원격 발주 | 미구현 | 부족 재고에서 바로 발주 생성, 상태 추적 |
| P0-3 | 매출 대시보드 | 거의 미구현 | 오늘/주간/월간 매출과 증감률 표시 |
| P0-4 | 직원 근태 관리 | 기반만 있음 | 출근/퇴근 기록, 근무 상태, 근무 시간 합계 |
| P0-5 | 본사-매장 커뮤니케이션 허브 | 부분 구현 | 공지/문서/채팅/문의/AS를 한 흐름으로 정리 |

---

## 2. 개발 순서

### 2.1 재고 부족/소진 알림

가장 먼저 진행한다. 이미 재고 조회/업로드/수량 조정이 있으므로 기존 도메인에 붙이기 좋다.

필요 문서: [05-inventory-alerts-requirements.md](05-inventory-alerts-requirements.md)

### 2.2 모바일 원격 발주

재고 부족 항목에서 바로 이어지는 업무 흐름이다. 재고 알림이 완성된 뒤 연결한다.

필요 문서: [06-mobile-order-requirements.md](06-mobile-order-requirements.md)

### 2.3 매출 대시보드

본사/점장 대시보드의 핵심 지표로 확장한다. 실제 매출 데이터 소스가 필요하므로 별도 도메인으로 설계한다.

필요 문서: [07-sales-dashboard-requirements.md](07-sales-dashboard-requirements.md)

### 2.4 직원 근태 관리

직원 승인/등록 흐름 다음의 자연스러운 확장이다. 급여 자동 계산은 후순위로 둔다.

필요 문서: [08-attendance-requirements.md](08-attendance-requirements.md)

### 2.5 본사-매장 커뮤니케이션 허브

공지, 문서, 채팅, 문의/AS는 이미 일부 구현되어 있다. 새 도메인을 크게 늘리기보다 홈/관리 화면에서 한 흐름으로 묶는다.

필요 문서: [09-communication-hub-requirements.md](09-communication-hub-requirements.md)

---

## 3. 공통 완료 기준

| 구분 | 완료 기준 |
|------|-----------|
| 서버 | 브랜드 격리(`brandId`)와 매장 격리(`storeId`)가 모든 조회/수정 API에 적용됨 |
| 앱 | STORE_STAFF / STORE_MANAGER / HQ_STAFF 역할별로 접근 가능한 화면과 액션이 구분됨 |
| 알림 | 사용자에게 필요한 실패/성공 메시지가 명확히 노출됨 |
| 테스트 | 핵심 서비스 테스트와 API 클라이언트 테스트가 추가됨 |
| 문서 | 데이터 사전과 ERD에 새 엔티티/필드가 반영됨 |
