# 매출 대시보드 요구사항

> 목적: 점장과 본사가 매장 매출 흐름을 빠르게 확인하고, 전기간 대비 변화를 볼 수 있게 한다.

---

## 1. 문제 정의

현재 홈/관리 대시보드는 운영 현황, 직원 승인, 문의/AS 중심이다. 매출 관련 타입 정의는 일부 있지만 실제 매출 도메인과 API가 없다.

매출 대시보드는 운영 판단에 필요한 지표를 앱 첫 화면 또는 관리 화면에서 확인하게 하는 기능이다.

---

## 2. 핵심 지표

| 지표 | 설명 | 우선순위 |
|------|------|----------|
| 오늘 매출 | 당일 누적 매출 | P0 |
| 주간 매출 | 이번 주 누적 매출 | P0 |
| 월간 매출 | 이번 달 누적 매출 | P0 |
| 전기간 대비 증감률 | 어제/지난주/지난달 대비 변화율 | P0 |
| 시간대별 매출 | 시간별 매출 추이 | P0 |
| 매장별 비교 | 본사에서 매장별 매출 비교 | P0 |
| 결제수단별 비율 | 카드/현금/이체/기타 | P1 |

---

## 3. 데이터 입력 방식

초기 구현은 외부 POS 실시간 연동 없이 수동 업로드 또는 내부 API 적재를 기준으로 한다.

1. CSV/엑셀 업로드
2. 서버 API 직접 등록
3. 추후 POS 연동

---

## 4. 서버 요구사항

### 4.1 SalesTransaction 엔티티

| 필드 | 타입 | 설명 |
|------|------|------|
| id | Long | 거래 ID |
| brandId | Long | 브랜드 격리 기준 |
| storeId | Long | 매장 |
| transactionDateTime | LocalDateTime | 거래 시각 |
| amount | Integer | 거래 금액 |
| orderCount | Integer | 주문 건수. 거래 단위면 기본값 1 |
| paymentMethod | PaymentMethod | CARD / CASH / TRANSFER / OTHER |
| source | String | MANUAL / EXCEL / POS |
| createdAt | LocalDateTime | 생성 시각 |

### 4.2 API

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/sales/summary` | 오늘/주간/월간 매출 요약 |
| GET | `/api/sales/hourly` | 시간대별 매출 |
| GET | `/api/sales/stores` | 매장별 매출 비교 |
| POST | `/api/sales/upload` | 매출 파일 업로드 |

### 4.3 비교 기간 정책

| 조회 기준 | 비교 대상 |
|-----------|-----------|
| 오늘 | 어제 같은 시간까지 |
| 이번 주 | 지난주 같은 요일까지 |
| 이번 달 | 지난달 같은 일자까지 |

비교 대상 금액이 0이면 증감률은 null로 내려주고, 앱에서는 `비교 데이터 없음`으로 표시한다.

---

## 5. 앱 요구사항

### 5.1 홈/관리 대시보드

- 오늘 / 주간 / 월간 매출 카드 표시
- 각 카드에 전기간 대비 증감률 표시
- 시간대별 매출 차트 표시
- 본사 권한에서는 매장별 비교 섹션 표시

### 5.2 권한별 표시

| 역할 | 표시 범위 |
|------|-----------|
| STORE_STAFF | 본인 매장 오늘 매출 요약 |
| STORE_MANAGER | 본인 매장 전체 매출 대시보드 |
| HQ_STAFF | 브랜드 내 전체 매장 비교 |
| ADMIN | 전체 관리 범위 |

---

## 6. 완료 기준

- 실제 서버 API에서 오늘/주간/월간 매출을 내려준다.
- 전기간 대비 증감률이 서버에서 계산된다.
- 시간대별 매출 데이터가 차트로 표시된다.
- 본사 계정은 매장별 비교를 볼 수 있다.
- 매출 데이터는 `brandId`와 `storeId` 기준으로 격리된다.
